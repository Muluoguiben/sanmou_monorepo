当前架构

首屏产品是 Advisor，不是托管自动化。架构上保留了向 Copilot/Autopilot 演进的接口。

截图 Advisor 主链路

Electron Renderer 选择、拖拽或粘贴截图，填写平台和账号标签，展示报告、历史和聊天。
->
Advisor API FastAPI 保存上传图片，校验 10MB 内图片，调用 mock 或真实视觉链路。
->
AdvisorLoop capture -> VisionSync -> RuntimeState -> Deriver -> ActionSelector -> AdvisorReport。
Vision Domains resource_bar、chapter_panel、recruit_panel、upgrade_dialog、mode_hub、city_buildings、team_panel、team_detail、popup。
->
Selector + Strategy Snapshot 候选动作生成、过滤、评分、优先级规则。建筑评分会读取 `data/strategy_snapshot.yaml`。
->
Report + Chat 报告固定 `executable=false`。聊天优先接 qa-agent QueryService，否则用本地 Advisor 回答。

自动化 runtime 已有的骨架

  1. Windows bridge 支持 dxcam 截图和 pyautogui 输入。
  2. `AutonomousLoop` 串起 observe、vision、derive、select、act、verify、trace、recover。
  3. `SafetyGuard` 默认在 observe/advisor 模式阻止输入，高风险动作要求人工确认。
  4. `VerifierRegistry` 默认要求点击类动作必须先声明 verifier spec。
  5. `TraceStore` 记录 state_before、vision、ranked_actions、execution、verification 和 recovery。

自动化 runtime 当前不能托管的原因

  1. 默认 `VerifierRegistry()` 没有任何 spec，点击类动作会被阻断。
  2. `claim_chapter_reward`、`upgrade_building`、`recruit_soldiers`、`attack_land`、`transfer_main_lineup_to_team`、`abandon_land` handler 仍返回 pending。
  3. 现有 recovery 主要是 stuck 后发送 ESC，缺少页面导航、弹窗策略和重试预算。
  4. 缺 `map_land` 和 `battle_result` 感知域，无法闭环出征和战报复盘。

目标自动化闭环

Bridge Health 窗口身份、截图 freshness、非黑屏检测、输入能力和坐标空间。
->
Perception + State 多域识别写入 RuntimeState 和 field_meta，并保留截图证据。
->
Safety + Verifier Gate 低风险动作有 verifier 才自动执行，中高风险动作默认人工确认。
Action Flow claim、recruit、upgrade 先闭环；attack、transfer、abandon 后置。
->
Post-action Verify 动作后重新截图，断言章节、兵力、建筑等级或倒计时变化。
->
Trace + Replay 每个 tick 都能用固定截图和 state 复现选择、执行结果和恢复策略。

知识链路

qa-agent 已经是可复用知识底座，不只是聊天壳。

正式知识库

`knowledge_sources` 覆盖 building、chapter、combat、hero、skill、solution、status、term 等域。

  • 34 个正式 YAML 文件
  • 武将、战法、状态、阵容分 bucket 管理
  • QueryService 返回 answer、evidence、coverage 和 confidence

视频证据链

Bilibili workflow 产出证据 bundle、视频知识、reviewed staging 和临时 knowledge_sources。

  • 优先 subtitle 和 conclusion
  • 可选 frame vision enrichment
  • 发布前走 staging/review

进入 Advisor 的方式

当前已有两条接入：chat 运行时查询，selector 离线 strategy snapshot。

  • Advisor API 按关键词调用 QueryService
  • qa-agent 导出 `strategy_snapshot.v1`
  • pioneer selector 用快照增强建筑优先级

迭代路径

路线应从 Advisor 可信度和低风险闭环开始，不先冲 48 小时托管。

M0 当前基线

截图 Advisor 产品化

目标是稳定读取截图、生成可解释报告、引用知识库、保存历史，并明确“不自动点击”。

  • 完成：桌面端上传、mock/vision 模式、报告、聊天、历史、kill switch 展示。
  • 补强：API 合约测试、视觉错误退化提示、报告字段说明。
M1 可信感知

截图 fixture 和视觉 eval

把现有多个感知域变成可回归资产，而不是只靠在线模型临场表现。

  • 建立 city/chapter/recruit/team/detail/upgrade/popup 的真实截图 fixture。
  • 每张截图配 expected JSON，统计 page/domain/entity accuracy。
  • 将 `field_meta` 细化到核心字段，记录 confidence/source/captured_at。
M2 低风险自动化

claim、recruit、upgrade 三类动作闭环

只做可验证、可撤回或低损失动作，且每个动作必须有 post-action verifier。

  • `claim_chapter_reward`：识别按钮、点击、验证 `chapter_claimable=false` 或章节变化。
  • `recruit_soldiers`：进入征兵、确认队伍和数量、验证兵力/倒计时/预备兵变化。
  • `upgrade_building`：只对白名单建筑执行，验证等级、倒计时或资源变化。
M3 安全 Copilot

人工确认的半自动开荒助手

高风险动作不自动执行，先让系统做观察、解释、排队和确认。

  • SafetyGuard 接配置，风险统一为 level/reason/confirm_required/irreversible。
  • 桌面端展示“可自动/需确认/已阻断”的执行状态。
  • qa-agent strategy snapshot 覆盖建筑优先级、土地风险规则和阵容提示。
M4 打地闭环

map_land + battle_result + 出征 verifier

打地是中高风险动作，必须等低风险闭环、trace、recovery、人工确认稳定后再做。

  • `map_land` 感知候选地、等级、可达性、距离和目标 bbox。
  • `battle_result` 识别胜负、战损、经验、重伤和后续恢复动作。
  • 连续失败或高战损进入 stop/recovery，不继续尝试。
M5 48 小时托管

长跑、复盘和人工接管

只有在低中风险动作都可 replay、可恢复、可解释后，才进入测试账号长跑。

  • Bridge watchdog：截图 freshness、黑屏、窗口偏移、server 重连。
  • Golden replay：固定截图序列复现感知、决策、执行和 verifier。
  • 运行手册：停机、回滚、日志保留、账号风险边界。
