## H06a-CR02 / HIGH (P1): concurrent old close invalidates new owner

Location: `packages/pioneer-agent/src/pioneer_agent/agent_harness/run_store.py:48-53` (`RunOwnership.close`).

Two threads may both pass `if self.active`. Pause the first immediately before assigning `self.active = False`; the second closes and a successor acquires; resume the first. The delayed old close clears `store._owner` even though it now belongs to the successor. For MemoryRunStore it additionally releases the successor's shared mutex, allowing a third acquisition. For JsonRunStore the original LocalLock is already closed, so the successor's OS lock remains, but its ownership handle is invalidated and subsequent operations fail. Sequential repeated-close tests do not cover this check/use interleaving.

Independent probe `test_concurrent_close.py` uses a real thread and `sys.settrace` to stop at the real assignment line, synchronized with Events and bounded waits. It never mutates private production fields. The exact instruction hook is intentional deterministic scheduling, not a lock mock. Results: one test, two failing subtests; memory reports successor invalid / third acquired; JSON reports successor invalid / third rejected. Atomic/idempotent close must retire only its own lifetime and release once, without clearing/releasing a successor. A changed implementation may require an additional revised scheduling probe; retain this original red source/log untouched.

Hashes: probe `918f4bad345192a011420b5ba3961d17cd7713d99b8dc633343b982130ea76fd`; raw log `f8e3f32f8323efdff5bb65988d8323d23fe920bd48b6e805f66426af5cfca70e`.

## H06a-CR03 / HIGH (P1): two runners share owner and lose accounting

Location: `packages/pioneer-agent/src/pioneer_agent/agent_harness/task_runner.py:38-44` and `run_store.py:57-71` (external ownership admission / shared mutable CAS cursor).

Passing the same acquired RunOwnership through the public `ownership=` argument to two TaskRunner instances permits both to restore independent budgets and execute. `asyncio.gather` yields two paused runs and eight actual fake tool calls, while the final checkpoint contains only four tool reservations, one step and `obs-1`. Both saves use the same owner object's advancing revision, so the CAS check does not distinguish these independent stale runner states. No threads or private-field mutation are needed. Admission or exclusive-use semantics must prevent independent runners sharing one ownership lifetime from overwriting spent ledger/state.

Independent `test_shared_external_owner.py`: one test, one failure (`4 not greater than or equal to 8`). This confirms an auditor report; coordinator says the author also discovered/fixed it in a later source, but that later source has not been reviewed here. The original red applies only to 44ad8aa.
