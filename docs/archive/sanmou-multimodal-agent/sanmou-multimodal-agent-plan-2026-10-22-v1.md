# 三谋多模态 Agent 设计基线 v1

> 归档于 2026-10-22，仅保留历史讨论；当前方案见 [v10](../../sanmou-multimodal-agent-plan-2026-10-23-v10.md)。

日期：2026-10-22，Asia/Singapore。版本：v1。

目标是搭建真正由可训练模型选择行动的三谋 Agent：通过 RAG 获取游戏知识，用固定视觉模型把截图转成观察，由经过 SFT 和 PPO 的文本策略选择动作，再由 Harness 执行、验证、记录和恢复。最终在 Lanull 的 Windows 上运行多个游戏客户端，每个窗口由独立 Agent 会话处理，在明确预算与停止条件内无人值守采样。

本文中的**已确认方向**来自本次用户选择，**初始设计**仍需工程验证，**现有实现**以当前代码为准。本次只落地设计记录，没有启动游戏、录制、API 或训练，也没有解除执行门禁。

## 已确认的方向

| 事项 | 当前结论 |
| --- | --- |
| 产品目标 | 完整游戏 Agent 加可验证的训练收益；简历描述以实际完成和评测结果为准 |
| 首版架构 | 分离式：固定视觉感知、RAG、可训练文本策略、Computer Use 执行器、Harness |
| 游戏运行位置 | 用户本机 Windows；暂不考虑云 computer 或云游戏 worker |
| 客户端组织 | 多开游戏客户端，每窗口一个独立 Agent；模型服务与知识库可以共享 |
| 账号与角色 | 同一登录账号在不同区服创建和推进不同角色，不是默认批量注册平台账号 |
| 多开证据 | 用户确认可多开客户端；同账号多角色并发在线、窗口与输入隔离仍需实测 |
| 感知模型 | 拟接入用户提供的 Gemini 3.8 Flash HIGH 配置；首阶段不训练视觉层 |
| 策略训练 | 人工示范 SFT，再以 SFT checkpoint 热启动 PPO；文本基模与 trainer 尚未选定 |
| 数据来源 | 完整任务 trajectory；用户可以先录几条示范 |
| 首轮任务 | 信息获取用于管线验证，章节瓶颈与建筑升级为核心，整备与低损打地后置 |
| 云 GPU | 排除云游戏 worker 不等于排除云 GPU；Colab 或其他训练算力部署独立待定 |

## 覆盖早期建议的决策

- 首版不采用一个 VLM 同时读图和决策。整个系统仍是多模态 Agent，但被训练的策略可以是纯文本模型。
- Qwen3.5-4B、9B 只是之前讨论过的候选，没有确定为当前文本基模；此前视觉 SFT／GRPO 的费用估算不能直接用于文本 PPO。
- 新角色可提供新的开局 episode，真实游戏的不可逆性不排除 episodic RL；但不能回滚到任意中间状态，也不能假设卡池、地图和资源完全相同。
- 真实多角色主线采用 PPO 方向，不把不同初始条件硬拼成同 prompt 的 GRPO 组；可复现起点的小任务可以保留 GRPO 作为后续实验。
- 完整三谋模拟器不是首要前置条件。先验证真实客户端采样，局部模拟可用于环境、奖励和训练器的单元测试。
- 云 Windows 与跨云游戏 worker 移出当前范围。
- 旧文档中的规则优先选择、低频 LLM 仲裁是现有实现与历史设计。新目标是让可训练策略真正选择动作，不只是解释规则答案。
- 新方向不取消截图新鲜度、目标绑定、输入授权、verifier、人工确认和 kill switch 等边界。

## 各部分职责

| 部分 | 输入与输出 | 边界 |
| --- | --- | --- |
| RAG | 目标、状态或查询 → 带来源、版本和适用范围的知识证据 | 提供规则，不代替实时画面，不授予执行权限 |
| 视觉感知 | 当前截图／ROI → 页面、可见字段、元素位置、未知项和证据 | 报告画面事实，不决定开荒路线 |
| 文本策略 | 目标、观察、RAG、历史、工具和约束 → 语义动作及参数 | 选择行动、补充观察、等待、重规划和停止 |
| Computer Use | 已授权语义动作 → 导航、点击、输入和执行事件 | 实现操作，不暗中替策略改选业务动作 |
| Harness | 上下文、动作、状态与反馈 → 运行闭环 | 身份、输入调度、预算、授权、验证、日志、恢复和接管 |
| 训练管线 | 审核示范或策略 rollout → adapter、版本和评测 | 只训练对应目标，不能把脚本能力归因给策略 |

闭环：观察 → 构造上下文 → 策略选择 → Harness 校验 → 执行 → 新画面验证 → 记录与重规划。

“基模”指可继续训练的开源 checkpoint，通常从 Instruct 起步；经过训练后它在系统里承担“策略模型”角色，不需要另外增加一个“基模大脑”。

## 视觉层与 RAG

### 模型配置

本次安全核对的文件是 `/Users/lanull/Desktop/sub2api-gemini-3.8-flash-high.env`。只记录非敏感选型：

- `GEMINI_MODEL=gemini-3.8-flash`
- `GEMINI_THINKING_LEVEL=HIGH`
- 文件还含凭据和自定义网关地址；这些值不复制到文档、轨迹或训练集。

当前 Gemini 客户端仍默认 `gemini-flash-latest`，没有接上上述文件中的 key、base URL、model 和 thinking 参数。本轮没有进行真实图片请求。后续显式接线后，用最小图片抽取请求验证实际路由、输出和计费。

训练对照期间固定模型 ID、prompt、schema、预处理和状态接口，并记录响应模型标识。`HIGH` 是思考档位，不是额外的游戏知识。

### 识别说明与知识的分工

视觉层提供三谋页面分类、资源／图标含义、单位、按钮状态、坐标约定和少量标注示例。首版按页面加载模板与字段字典，不必先为它建立完整攻略检索。

视觉模型输出状态 JSON，Harness 再组装策略 prompt。看不到的字段保留未知；不能根据攻略推测当前兵力、体力或资源。Schema 合法不等于字段读对。

复用 Pillow 处理图片。现有全帧最长边限制为 1280，小字与密集数字需要从原图裁剪 ROI；保留裁剪偏移、缩放及 capture geometry。OCR 可辅助局部数字，不作为唯一视觉理解方案。当前部分 confidence 是硬编码常量，不当成识别准确率；使用独立标注评测。

RAG 主要为策略提供赛季、武将、战法、建筑前置和资源规则，带来源与版本；确定性比较可交给代码。现有 alias、词项和中文 n-gram 检索可以复用，当前没有向量库，不因 RAG 名称就默认重建。

## Windows 本机多客户端

每个 Agent 会话绑定 PID、窗口句柄、区服和角色身份。任务、观察、历史、episode、动作账本和轨迹分开保存；视觉 API、文本模型和只读知识库可以共享，不必每窗口加载一份完整模型。

多开窗口与同账号多角色并发在线是两项验收。若出现互踢，改为角色串行调度，不把打开多个窗口等同于已成功并行采样。

现有 Bridge 输入依赖前台。首版观察和推理可以并发，鼠标键盘通过统一调度器互斥执行。输入事务包括重新核对窗口、角色、最新画面、目标与坐标；不能只锁鼠标按下而让另一个 Agent 在验证中途抢焦点。资源等待等长等待不持有输入锁，需要前台的验证重新调度。

现有单 live source 约束与 runtime 单实例锁应按角色和资源边界改造，不能简单删除所有锁。未验证前不启用并发后台注入输入。

### 自动初始化

目标流程：启动客户端 → 登录态检查 → 选服 → 创角 → 选州与职业 → 教程 → 预算内抽卡 → 起始快照 → 策略任务。

首版选服范围、州、职业、卡池和券预算来自配置。固定初始化由可恢复状态机执行；有明确策略选择空间的步骤后续再训练。

首次登录、新设备扫码或必须本人完成的验证由用户接管；凭据不进入示范或模型上下文。主玩区服、已有角色、付费入口不因“全流程”自动获得操作许可。

不可逆动作使用持久账本：意图 → 派发 → 验证 → 确认。抽卡或领奖超时先核对扣券、入库和奖励状态，无法判定就隔离，不能直接重复点击。恢复依据当前真实状态，不回放旧世界快照。

无人值守需要持久任务队列、角色游标、watchdog、预算、连续失败上限、kill switch 和异常通知。正常路径自动推进；登录验证或不可逆结果无法确认时暂停对应会话。

## SFT 数据与轨迹

### 数据单位

- **角色成长轨迹**：一个区服角色从初始化到成长的完整记录，可以包含多个短任务。
- **Episode**：具有目标、开始条件、预算和结束判据的一次短任务尝试。
- **决策步**：当时可见上下文、动作提议、实际执行与环境反馈。
- **训练样本**：由审核轨迹导出的多轮序列，或“历史前缀 → 下一动作”。

不能把互不相关的状态问答当成长程轨迹，也不能把同一轨迹的相邻帧随机分到训练和测试。

### 统一记录格式

| 层级 | 必要内容 |
| --- | --- |
| TaskSpec | 目标、开始条件、动作范围、资源／时间预算、成功判据、版本 |
| Episode | 匿名账号标识、区服角色、父轨迹、起始卡池／资源等条件、策略与环境版本 |
| Observation | 操作前截图引用、时间、感知状态、未知字段、感知版本 |
| Context | 实际给策略的目标、观察、RAG 快照、历史、工具和约束 |
| Action | 语义动作、参数、actor_origin、模型提议、实际执行、拒绝或接管原因 |
| Feedback | 工具结果、新观察、状态变化、独立验证证据 |
| Outcome | 成功、失败、截断、接管、奖励分项与版本 |
| PPO 扩展 | 行为策略版本、准确输入输出 token、旧 log-prob、value、action token mask、终止／截断 |

`actor_origin` 区分 human、script、teacher、policy。语义动作与物理点击分开，例如“升级目标建筑”可包含执行器内部多个点击。

原始轨迹不改写，标注独立保存。密码、验证码不进入训练材料；截图身份信息按隐私边界审核。工具反馈、后帧和执行结果不能由模型编造。

### 构建步骤

1. 定义短任务和完成条件。
2. 录制人工操作、关键帧、输入事件、时间与窗口。
3. 使用固定感知配置生成决策点观察。
4. 分段并标注语义动作，审核关键字段、目标和结果。
5. 关联当时可用的 RAG 和历史。离线重建检索要标明来源，只依据当时已知信息，不用后来的正确动作反向构造输入。
6. 审核整条轨迹后导出训练样本。

终局成功不代表每步正确。错误动作不直接当正标签，正确的恢复步骤可以保留。规则唯一动作可教格式和约束，重复它们不能证明策略学习。

### 首批示范

用户先提供 3–5 条完整示范，验证录制、接口和标注：

1. 已登录选服页 → 创角 → 选州 → 教程完成。
2. 固定预算抽卡 → 查看所得武将、战法及当前队伍。
3. 条件齐备时检查、升级、验证章节条件。
4. 资源或前置不足时补充观察、补缺、继续推进。
5. 弹窗、无效点击或错误页面后恢复或明确停止。

后续一起设计 30–50 条短任务轨迹作为试点，覆盖不同条件与恢复分支；该数量是工程起步建议，不是稳定泛化保证。

### 训练方法

从可微调文本 Instruct checkpoint 起步，优先试 LoRA。感知层保持固定，离线 SFT 可预计算观察和检索输入，不必每个 epoch 重复调用 Gemini。

首轮可导出“截至当前的历史 → 下一动作”，短轨迹也可整段多轮训练。只对审核过的目标 assistant 动作计算 loss，输入、RAG 和工具回包不作为模型要生成的环境结果。验证所选 chat template 的工具调用 mask，不能只设参数就假设正确。

长轨迹裁剪和摘要只使用当前前缀，训练与部署沿用相同上下文构造逻辑。操作后状态用于验证动作或下一条样本，不能泄漏到前一步输入。

## Episode 课程

| 子任务 | 优先级与用途 | 验证依据 |
| --- | --- | --- |
| 选服、创角、固定教程 | 初始化与 SFT，不重点做策略 RL | 角色、教程阶段与功能开放 |
| 预算内抽卡 | 固定流程，不按卡牌品质奖励 | 扣券、结果／入库与预算 |
| 跨页面补齐信息 | RL 管线小试验 | 字段与独立证据一致，不猜未知 |
| 章节瓶颈与建筑前置链 | 首个核心策略任务 | 目标条件、建筑等级与必要奖励证据 |
| 征兵与队伍整备 | 第二批 | 最终兵力／状态，不能只看计时开始 |
| 抽后配队 | 后置，先配置 SFT | 配置合法与战斗质量分别验证 |
| 选地与低损占领 | 第二阶段核心 | 本次目标归属、战报、损耗和时间 |
| 异常恢复 | 各任务变体 | 恢复原目标，没有重复消耗 |

章节、等级、州、职业和预算以实际新号客户端确定；当前 S15 runbook 不可直接作为新区 S1 的标准。

### 首个任务规格草案

示例目标：完成当前章节要求的一次建筑升级。

- 开始：教程已结束；角色、章节和建筑身份明确；目标未达成。
- 目标：指定建筑达到指定等级，对应章节条件完成；是否领取整章奖励需明确写入规格。
- 动作：查看、查询、领取可领取奖励、升级允许的前置或目标建筑、等待、结束。
- 预算：首测可从 20 次策略决策、10 分钟有效运行起步，采样后调整；默认不使用付费货币。
- 成功：新画面、目标身份和独立 verifier 均支持完成。
- 失败：策略宣告结束但未达标、独立规则证明目标已不可达，或耗尽任务预算；正常的未完成中间状态继续执行。
- 基础设施截断：设备／服务故障或无法取得可信观察，单独记录。
- 目标开始前已完成则跳过，不能重复获得成功奖励。

Episode 结束后角色继续向前，不伪装成已回滚。相邻 episode 仍共享角色来源和前序影响。

## 奖励函数草案

```text
R = S - 0.1 × min(I / 5, 1) - 0.1 × min(D / 5, 1)

S：独立验证成功为 1，明确任务失败为 0
I：经核实的无效动作次数
D：经核实的重复且无进展操作次数
```

系数待实验校准。必要观察、合理等待不自动扣分；I 与 D 不重复计同一步。主要奖励只结算一次，不按点击数量、模型声称完成或抽卡稀有度计分。

暂不把资源净余额差当成本，因为领奖和自然产出会抵消支出。建立动作级支出账本后再增加预算归一的效率项。

非法动作由 Harness 拦截；若人工或脚本改选动作，记录原提议和实际执行，不把替代行动的成功归给原策略。奖励代码依据实际证据，独立于策略的自我报告。

基础设施故障不直接记策略失败，也不统一填零分；先隔离不能确认的片段，保留有证据的有效 transition，并在实现中正确处理终止、截断和价值 bootstrap。策略耗尽预算单独判定。

## PPO 与 SFT 衔接

SFT 从人工或审核示范学习动作；PPO 使用当前策略新产生的 rollout，包括成功与失败。旧示范加 reward 不等于 PPO。

固定初始化、感知、知识和执行器都记录事件，但 PPO 仅更新 policy 生成的动作 token。工具回包、观察和脚本步骤不算策略输出；接管段不能整体归功于模型。

人工或策略外脚本改选业务动作时，在接管边界切断可学习的 rollout；接管后取得的成功奖励不能沿回报传播到前段。训练器对前段明确处理截断与可信的价值 bootstrap，证据不足则隔离。接管后的新片段重新标记起点与来源。执行器按照原语义动作展开低层点击不属于这种策略接管。

### 批次闭环

1. 以通过检查的 SFT checkpoint 发布策略 v1。
2. 一批 Agent 使用固定行为策略采样，各窗口保存独立 episode。
3. 保存实际输入、动作 token、旧 log-prob、value、反馈和奖励，不在轨迹中途热换权重。
4. 计算回报与优势，更新 actor 和 critic。
5. 固定回归集和保留任务检查候选版本；不通过就不发布。
6. 下一批采样使用通过检查的新版本。

初期采样和训练可交替进行，不要求同时常驻多份完整模型。PPO 的 actor、critic、reference 或其他稳定项、生成缓存和更新配置都会影响显存，要在选定模型后小跑。

不同卡池、资源和地图作为任务条件进入策略与价值估计。PPO 不要求精确复制每个起点，但差异本身不保证有效学习。真实多角色主线不硬拼 GRPO 组；可复现起点的小任务可另做 GRPO。

具体 PPO trainer 未定。早期提到的 TRL GRPO 接口不是 PPO 已接通的证据；模型、库、工具模板、概率重算和 mask 都需验证。

## 模型与算力待定项

讨论覆盖 Qwen、DeepSeek、GLM、Kimi、NVIDIA、Google、Meta。文本策略按中文状态理解、RAG 使用、工具参数、决策质量、训练支持和成本筛选，不再仅以视觉能力过滤候选。

此前讨论的 Qwen3.5-4B／9B 并未定稿。Gemini 作为固定视觉服务，也不能代替可训练策略产生 on-policy rollout。

此前 Colab 截图为 A100 80GB、191.39 CU、约 6.77 CU/小时，算术约 28.27 GPU 小时；这是截图时的余额和费率，不是当前余额或连续运行保证。视觉 SFT／GRPO 的旧费用区间均为估算，不能沿用为文本 PPO 报价。

文本基模、LoRA、critic、trainer、GPU 部署和费用上限待定。游戏与录制已确定先在本机 Windows，云游戏 worker 不在当前范围。

## 评测

固定感知、RAG、Harness、任务和上下文规则，对比规则策略、未微调文本策略、SFT 策略、SFT 加 PPO 策略。

- 感知：页面、关键字段、目标定位和未知项。
- 策略：合法性、参数与目标、信息获取、成功率、无效动作和效率。
- 系统：窗口／角色隔离、输入串扰、重复消耗、恢复、轨迹完整性与预算停止。
- 训练：mask、loss／梯度、保存重载、推理与训练概率一致性、奖励分项和价值指标。

当前是同一账号多角色，主要按区服角色、完整轨迹和任务族划分；相邻步骤不跨集合。按卡池组合、版本、区服、开服时间等条件分层比较，记录玩家干扰。

脚本跑通教程不是策略提升，抽卡幸运不是规划提升，模拟器提升不自动代表实机提升。Verifier 和 reward 也需要成功、未变化、错误目标、超时和冲突状态的反例测试。

## 实现顺序

| 阶段 | 交付 | 验收 |
| --- | --- | --- |
| P0 数据契约 | 账号／角色／窗口／episode 标识、TaskSpec、动作与 trace | 可审核样例、未知值与来源明确 |
| P1 单窗口采集 | 固定感知、3–5 条示范、标注与 holdout | 原始证据、标签和切分正确 |
| P2 初始化及低风险闭环 | 创角教程预算抽卡、章节／建筑与 verifier | 受控实机完成，无重复消耗 |
| P3 SFT | 文本模型、LoRA、保存重载与基线评测 | 离线和 shadow 表现可解释 |
| P4 双客户端 | 每窗口 Agent、共享模型、互斥输入、独立轨迹 | 在线稳定，无窗口串扰 |
| P5 PPO 小批次 | rollout、奖励、actor／critic 更新、复测 | 概率与 mask 正确，保留集结果可信 |
| P6 有限无人值守 | 账本、恢复、预算、通知、评测发布 | 先有限时长，再开放过夜批次 |

契约、输入隔离和验证可并行准备；正式操作与发布须通过对应验收。下一步先一起确定首批短任务，再到 Windows 录制，不直接启动大规模跨服或无人值守。
