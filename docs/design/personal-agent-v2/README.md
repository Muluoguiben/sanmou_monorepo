## 页面分工

| 页面 | 负责什么 | 能走到哪里 |
|---|---|---|
| 对话 | 下达目标、询问进度、讨论战况与资料 | 创建任务、任务详情、知识详情、玩家偏好 |
| 总览 | 看当前角色、重点任务、待确认事项和简报 | 任务详情、对话、战报、知识库 |
| 我的任务 | 查看任务及进度，暂停、取消、接管 | 三步确认向导、任务详情、运行记录 |
| 角色与设备 | 查看区服角色、连接状态与角色偏好 | 切换角色、连接流程、偏好设置 |
| 战场与战报 | 预览PVE与PVP信息布局，查看目标和战报 | 目标详情、任务安排、战报复盘、聊天 |
| 知识库 | 三类知识来源、搜索、待审资料 | 导入、详情、审核、引用到对话 |
| 运行记录 | 查看做了什么、为什么做以及结果 | 单步详情、引用资料 |
| 偏好与授权 | 按角色保存资源预留、停止时间和通知偏好 | 模拟断连／恢复、重置演示 |

## 主要交互流程

1. **安排任务**：对话提出目标或点击新建任务 → 选择角色 → 确认允许操作、资源预留和停止时间 → 展示摘要 → 确认创建 → 任务详情。
2. **持续执行**：任务详情点“推进一步” → 更新进度和运行记录 → 完成后生成聊天汇报。
3. **暂停与接管**：暂停保留进度；人工接管暂停该角色的自动任务；交还后先检查状态、保持暂停，由用户选择继续。
4. **异常与恢复**：模拟断连 → 任务等待连接且无法推进 → 重连 → 保持暂停 → 用户继续。取消的任务不会恢复。
5. **切换角色**：运行中先提示暂停；各角色任务、聊天、偏好和接管状态分别保存。
6. **使用攻略**：添加标题和来源 → 待审核 → 查看内容与出处 → 审核通过 → 在聊天中引用。
7. **PVP设计预览**：切换战场页的PVE／PVP，仅改变预览内容，不改变角色实际阶段或任务授权。

## 交互边界

- 所有角色、任务、资源、战报和资料均为示例。模型输出由本地演示逻辑生成，不是真实AI回答。
- 任务不会自动操纵游戏。语音按钮不申请麦克风；资料导入不抓取外部链接；连接按钮不连接真实设备。
- 设置只作为新任务默认值，不会改变已确认任务预算。
- 本原型重点验证页面关系和交互，不替代执行协议、训练验收或真实客户端测试。

## 文件与验证

已通过32项浏览器交互与布局检查：8个页面、四类能力入口、任务创建与取消、暂停接管、角色隔离、断连恢复、知识审核、偏好保存，以及390px窄屏布局。没有浏览器脚本错误或外网请求；结果见[verification.json](verification.json)。

- `app.js`：页面壳、总览、对话、任务与状态交互。
- `secondary.js`：角色、知识、战场、记录、设置页面。
- `styles.css`／`secondary.css`：基础样式；`theme-soft.css`：v2温和主题。
- `previews/`：浏览器实际截图；`verification.json`：交互检查结果。
- `verify.mjs`：可重复的浏览器检查。通过 `PLAYWRIGHT_MODULE`、`CHROMIUM_PATH`、`PREVIEW_URL` 指定本机工具与预览地址。
